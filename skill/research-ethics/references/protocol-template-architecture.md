# 中国通用、代码化研究计划书架构

## 目标

不要把某一份 Word 或某家医院的表格当作模板事实源。使用 `protocol-coverage-matrix.yaml` 作为章节与字段的机器可读规格，并由代码稳定生成 Markdown、Word、HTML 或其他渲染结果。

当前优先实现**中国大陆通用层**：它将中国国家规则、V1 登记备案字段和研究设计质量指南组织成可复用的研究计划书骨架；不以任何具体医院为前置条件。

## 资料与权威层级

1. **中国大陆规则包**：决定法律、伦理与监管基线。当前唯一已实现的国家／地区配置是 `china-mainland`。
2. **平台规则树**：决定国家医学研究登记备案信息系统需要收集的最小事实与条件分支；当前平台观察范围仅为 V1 观察性研究。
3. **研究设计质量指南**：例如 STROBE、STARD、RECORD；用于提高方案完整性，绝不写成法定格式要求。
4. **项目事实层**：来自用户确认的研究问题、对象、数据、人员、经费和附件；模板、翻译器和 AI 都不得虚构这些事实。
5. **可选医院补充层**：若使用者自愿提供本院模板或要求，可在私有工作区叠加章节顺序、附件、流程和表述；它不是生成中国通用骨架的前置条件，也不进入公开 skill 或 Git。

## 同源双语原则

同一研究不能靠两份互不关联的中文／英文 Word 维护。底层以结构化研究事实为唯一项目事实源，并为每个可翻译事实记录：中文原值、英文配对值、来源、确认状态和适用范围。

```text
已确认的研究事实（唯一项目事实源）
  ├─ 中文计划书骨架／中文填写稿
  ├─ 英文配对计划书骨架（按需生成）
  └─ ChiCTR 公开路线的中英文配对字段
```

- 中文是中国通用层的默认和主要语言。
- 用户明确需要双语时，生成中文与英文的同源版本；英文是待核对的配对内容，不能被表述为已由用户确认的事实。
- 选择 `public-on-chictr` 时，平台实际要求的英文配对字段必须进入确认流程；选择 `private` 时，英文计划书可以按用户要求生成，但不伪称为平台必填。
- 英文翻译与平台英文填报是不同概念：前者是研究资料输出，后者受平台路线、字段和用户确认共同约束。

## 模块装配

```text
中国大陆通用基线
  + 观察性研究基础模块
  + 诊断试验模块（如适用）
  + 条件模块（多中心／生物样本／公开／国际合作／豁免同意／弱势群体）
  = 中国通用研究计划书骨架

中国通用研究计划书骨架
  + （可选）医院补充层
  = 某医院可调整的提交版本
```

生成器只输出适用章节、填写提示和证据来源；它不代写研究事实，也不宣称通过伦理审查、满足未提供的医院格式或已经完成平台提交。

## 当前实现状态

- 已实现：`china-mainland` 下研究者发起观察性研究及诊断试验条件模块的中文**研究资料版骨架**。
- 已实现：`protocol-template-language-pairs.yaml` 将每个既有 `module_id`、`chapter_id` 与受控英文标题／写作提示配对；生成器可输出 `zh`、`en` 或 `bilingual` Markdown，并可把生成的 Markdown 渲染为 Word 骨架。
- 待实现：从真实、已确认研究事实自动形成完整的中英文段落；ChiCTR 公开路线的英文平台事实仍由现有两阶段确认工作流控制。
- 未实现：干预性研究、产品注册路线、其他国家／地区规则包、从完整计划书自动抽取所有字段，以及可选医院补充层。
- 日本或其他国家／地区必须建立独立的国家规则包；可复用项目事实模型，但不能把中国规则简单翻译后套用。
## 语义组合层：事实、段落和双语配对

计划书生成不能以“逐句改写 Word”作为规则来源。代码化生成采用三层分离：

```text
覆盖矩阵（章节、顺序、适用条件）
  + 语义组合规则（段落／小节／清单／表格的适用条件）
  + 私有事实模型（已确认与待确认的 statement_id）
  = 中文、英文或双语计划书
```

- `protocol-semantic-composition.yaml` 规定每一章节应使用的表达形态。叙述性章节按完整论点组合 2–5 个相关陈述，不能依句号、原方案换行或来源摘录断段。
- 同一章节出现互不混杂的主题时必须拆成有标题的子节。当前明确规定 `P-18` 分为“研究结果发布”“数据共享”“数据再利用边界”，而不是一个混杂章节。
- 定义、变量、角色和权限使用逐项清单；纳入／排除／退出使用标准清单；操作过程使用步骤清单；附件使用核对清单。只有三条及以上同构记录适宜横向比较时才使用表格。
- 私有事实模型的每条陈述都有稳定 `statement_id`、中文与英文值以及确认状态。双语生成从相同 ID 读取两种语言，避免“中文写完后临时翻译”导致事实、范围或段落逻辑漂移。
- 缺失事实保留显式待确认提示；生成器不得从研究标题、文献或常识猜测补全。合成事实模型用于回归测试，真实方案仅作用户受控的私有验收样本。
- 默认 `presentation_status` 为 `content_structure_draft`。它与内容正确性分开：前者只声明“可审查的内容与结构已经生成”，不声明版式已经美化、符合某医院品牌或完成最终分页。视觉质量须走独立的 Word／PDF 审查与机构模板适配流程。
