# 代码化研究计划书模板架构

## 目标

不要把某一份 Word 当作模板事实源。使用 `protocol-coverage-matrix.yaml` 作为章节与字段的机器可读规格，并由 `scripts/render_protocol_template.py` 稳定生成 Markdown 骨架；Word、HTML 或院内格式都应由同一规格另行渲染。

## 资料与权威层级

1. **国家／地区规则包**：决定法律、伦理与监管基线。当前只实现 `china-mainland`。
2. **平台规则树**：决定登记备案需要收集的最小事实与条件分支。
3. **研究设计质量指南**：例如 STROBE、STARD、RECORD；用于提高方案完整性，不应写成法定要求。
4. **医院补充层**：决定本院章节顺序、表单、附件、风险说明和流程；必须由该医院提供或确认。
5. **项目事实层**：来自用户已确认的研究问题、对象、数据、人员、经费和附件，永远不能由模板虚构。

## 模块装配

```text
中国大陆基线
  + 观察性研究基础模块
  + 诊断试验模块（如适用）
  + 条件模块（多中心／生物样本／公开／国际合作／豁免同意／弱势群体）
  + 医院补充层（尚待提供）
  = 项目专属研究计划书骨架
```

生成器只输出适用章节、填写提示和证据来源；它不代写研究事实，也不宣称通过伦理审查或满足未提供的医院格式。

## 当前实现状态

- 已实现：`china-mainland` 下的研究者发起观察性研究，以及诊断试验条件模块的**研究资料版骨架**。
- 未实现：医院补充层、干预性研究、产品注册路线、其他国家／地区规则包，以及从完整计划书自动抽取所有字段。
- 下一次资料工作：在私有工作区对已授权的既有方案和目标医院模板进行“章节／字段库存”提取；只写入脱敏的结构性结论，并与此覆盖矩阵做差异审查。
